# V3 — images, OCR, and visual retrieval

V3 makes screenshots and diagrams searchable alongside notes and code. The earlier build already had local OCR, CLIP, and file-level fusion; this milestone completes their evidence preview, capability status, and acceptance checks.

| Capability | Implemented behavior |
| --- | --- |
| Image indexing | PNG/JPEG, bounded decoded pixels, EXIF-corrected thumbnails, separate image/text vectors |
| OCR search | Offline English Tesseract, literal word search and semantic search over recognized text |
| Visual retrieval | Local CLIP text-to-image similarity; image-description queries and weighted file fusion |
| Scanned PDFs | OCR on pages without native text, page-specific thumbnails and page provenance |
| Evidence preview | Query-matched OCR words highlighted over the correct image; scalable coordinates and hide/show control |
| Capability status | Library reports OCR and CLIP availability without loading models or starting inference |
| Empty results | Default single-keyword searches require literal evidence; weak visual/text neighbors remain gated |
| Failure handling | OCR failure preserves image/vector retrieval; missing tools/weights have actionable status/errors |

## Try V3

1. Restart Fileora and refresh the browser. Open **My library** and check **Search inside images**. The usual Windows start script enables OCR and CLIP; the models/tools from the existing setup are reusable.
2. Rescan existing folders. Image/PDF provenance and PowerPoint OCR cache identity updates refresh affected content. Other unchanged file types retain their revisions and text embeddings are reusable.
3. Select **Images** and search for words visible in a screenshot. Open the result: matching recognized words are highlighted. **Hide highlights** shows the unobstructed image.
4. Search a phrase describing the image, such as “a diagram of virtual memory”. Semantic mode can explore related concepts, including a single word. Default single-keyword hybrid queries stay literal to avoid misleading BCNF-style matches.
5. A scanned PDF returns its page label, recognized excerpt, and highlighted page thumbnail. **Open original** keeps the PDF page anchor. Embedded PowerPoint OCR uses slide/image provenance and matching highlights when OCR succeeded.

If OCR or CLIP is missing, stop Fileora and rerun setup, then restart and rescan. OCR can misread text; visual similarity is not proof that a keyword exists in the image. Highlighting uses recognized words, not inferred concepts. Old locators without dimensions remain viewable but receive no guessed overlays until rescanned. Audio/video stays skipped unless explicitly enabled.

## Verification and scope

`scripts/check.ps1` runs correctness, type/format checks, frontend tests, and the production build. Focused V3 checks are `pytest backend/tests/test_images.py -q` and `npm run test:e2e -- images.spec.ts` against an authored-demo catalog indexed with OCR and vision enabled. Browser checks verify actual OCR highlights, show/hide behavior, empty results, capability status, aligned mobile previews, and localhost-only page requests. API tests cover preserving visual indexing when OCR fails and similarity-floor abstention.

Real portable OCR, MiniLM, and CLIP were exercised on the 17 authored demo files plus a separately generated single-page scanned PDF. The published [V3 image report](../evaluation/reports/v3-images.json) uses the existing 30 image queries and judgments over three synthetic, text-heavy screenshots. OCR, CLIP-only, and fused configurations share the indexed image corpus and record model/profile/catalog identities. These are smoke measurements, not representative personal-library recall. All 30 queries are answerable, so the report cannot estimate no-match false positives; separate regression checks cover nonexistent keywords.

| Retrieval branch | Correct first result | Warm p95 query time (CPU) |
| --- | --- | --- |
| OCR lexical | 30/30 | 27 ms |
| CLIP-only | 12/30 | 32 ms |
| Fused hybrid | 30/30 | 69 ms |

The measurement ran serially after the browser checks and builds had finished. Warm times come from one immediate repeat of each query after its initial search, excluding model loading; they do not measure indexing or OCR time. CLIP-only misses on this text-heavy fixture demonstrate why OCR remains part of image search.

Coordinate tests cover thumbnail scaling, page provenance, malformed/out-of-bounds boxes, and duplicate boxes. Overlays match the rendered image bounds on desktop and mobile. Boxes from image OCR and scanned PDF pages carry their source dimensions and preview identity; PowerPoint cache entries retain the dimensions used for recognition before thumbnail resizing.

## Limits and engineering concepts

OCR is English and machine-printed text; handwriting and multilingual accuracy are not validated. CLIP is weak on dense technical text, which is why OCR and visual vectors remain separate retrieval branches. Scanned-PDF OCR runs only when a page has no native text; mixed pages and reading order can lose content. PowerPoint image OCR is bounded and can be partial. Full slide rendering, image-to-image uploads, SmartArt/equation extraction, OCR text correction, and video OCR overlays are outside this milestone.

Understand **coordinate systems** (recognition image versus thumbnail versus CSS display), **modality-specific embeddings** (MiniLM and CLIP scores cannot be directly compared), **fusion versus duplicate evidence**, **literal match versus visual similarity**, and **model/preprocessing identity**. Preserve those distinctions in an interview and when reporting retrieval metrics.
