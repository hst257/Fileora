# V4 — audio, video, and timestamp evidence

V4 lets you find a spoken phrase or a sampled lecture slide and inspect its location in the original recording. Earlier builds contained the media extractor; this milestone completes its capability status, evidence controls, frame provenance, and acceptance checks.

| Capability | Implemented behavior |
| --- | --- |
| Audio | WAV/MP3/FLAC decoded locally; English Whisper base.en transcription with segment intervals |
| Video | MP4/MKV sampled every 10 seconds; near-duplicate frame suppression; optional local OCR and CLIP |
| Retrieval | Transcript/OCR text participates in lexical and semantic search; visual frame vectors participate in file fusion |
| Evidence | Correct sampled-frame thumbnails, query-word OCR highlights, and clickable timestamp matches |
| Playback | Audio/video seeks to the selected evidence; changing a timestamp seeks the existing player without autoplay |
| Readiness | Library distinguishes disabled media, missing decoder/speech packages, and missing local speech weights |
| Recovery | A missing/broken speech engine preserves video frames with a partial-transcription note; audio-only failures remain actionable |
| Bounds | Frame intervals and transcript timestamps stay within known recording duration; browser seek targets are bounded |

## Enable and try

Stop the current Fileora server with Ctrl+C before setup. In the project directory:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -Media
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Media
```

Setup prepares the optional media packages and pinned local Whisper model. Existing MiniLM/CLIP models are reusable. Open **My library → Search inside recordings** and turn on **Transcribe audio and video**, then add a recording folder and **Rescan library**. The Library control saves your choice for future launches; new catalogs start with media off. You can override the saved choice with `start.ps1 -Media` or `-NoMedia` (`--media` / `--no-media` in the CLI). Changing the Library control requires scans to be idle. Previously indexed evidence remains in the catalog when processing is disabled.

The original `computer_science_lecture.mp4` demo is deliberately silent: its searchable evidence comes from slide frames. The WAV tests spoken words. Newly generated demos also include `computer_science_narrated.mp4`, which combines the slide video and speech so video transcription can be tested directly. An older `MEDIA_DISABLED` file status may need an enabled-media rescan to become searchable again.

Choose **Audio** and search for a spoken phrase, or **Video** and search for words or a description of a lecture slide. Open the result, choose a timestamp, and press Play. The original-file link also carries the time anchor. A browser that cannot decode the original codec shows a recovery message; download/open the original in a local player. Fileora does not transcode your source recordings for browser compatibility.

Rescan existing media after upgrading so frame thumbnails, OCR coordinates, and bounded transcript intervals are refreshed. Unchanged text embeddings can be reused. A transcript-only result receives a frame thumbnail only when a sampled frame covers the matching interval; it never substitutes an unrelated frame from the same file.

## Verification and measurements

`scripts/check.ps1` runs backend correctness, format/type checks, frontend tests, and the production build. `npm run test:e2e -- media.spec.ts` checks real video OCR highlights, timestamp playback, multiple audio match jumps, local capability status, mobile overflow, and localhost-only page requests. The existing audio browser check also verifies seeking the original WAV. Backend checks cover byte-range preview requests, literal no-match behavior, near-duplicate sampling, partial-video recovery, bounded transcription intervals, readiness, and media-specific pipeline identity.

The isolated validation catalog contains the 17 authored demo files and two authored media fixtures: an approximately 87-second synthetic English WAV and a silent MP4 of the same three teaching sections. Real CPU Whisper, portable OCR, MiniLM, and CLIP were used. A separately muxed narrated MP4 was also decoded and extracted, producing 13 transcript segments and three sampled frames. It remains an ignored validation fixture, outside the published retrieval benchmark.

Reproduce the synthetic speech report against a stopped validation catalog:

```powershell
.venv/Scripts/python.exe scripts/media_report.py --data-dir .fileora/v4-validation --models-dir .fileora/models --output evaluation/reports/v4-media.json
```

The report records model/profile/catalog identities, token-normalized word error rate (WER), retrieval metrics, and evidence interval overlap for the 20 existing media queries and independent section judgments. These queries share one recording and are all answerable. File-level retrieval is easy in this small fixture; temporal evidence recall and WER are more informative. This does not measure representative lecture quality, timestamp error against human-aligned words, or no-answer false positives.

The [V4 report](../evaluation/reports/v4-media.json) measured the following on CPU:

| Measure | Authored-fixture result |
| --- | --- |
| First-result hit rate | 20/20 queries |
| Evidence interval overlap recall | 20/20 queries |
| Token-normalized WER | 6.48% (7 edits / 108 reference words) |
| Warm query p95 | 42 ms |
| Refresh of the two media files | 18.6 seconds; 17 unchanged demo files skipped; no failures |

Warm latency uses immediate repeated queries after the initial search and excludes model loading. Indexing time includes OCR/transcription and is separate from search latency. No-answer false positives are undefined in this all-answerable benchmark; nonexistent-keyword regression checks cover that behavior separately.

## Limits and concepts

Transcription is English, with approximate Whisper segment boundaries rather than word alignment. Compression, pronunciation, noise, and technical terms can cause recognition errors even on synthetic speech. Frame sampling can miss short-lived visuals; average-hash suppression can remove similar slides. OCR/CLIP setup is independent of speech setup. A missing speech engine can leave a video searchable only through its frames.

Non-media files default to a 50 MB size limit; media is instead bounded by four hours and 1,500 sampled frames. These limits and child-process timeouts are not hard memory limits. Video decoding visits intermediate frames, and CPU transcription can take substantial time. Changed recordings repeat extraction, and long-library throughput has not been benchmarked. Browser playback depends on the source codec; original content is served with byte-range support.

Understand **temporal provenance** (a transcript interval versus a sampled visual interval), **approximate speech recognition**, **deduplication versus missed scenes**, **modality-specific retrieval and fusion**, and **range requests versus transcoding**. Cite the synthetic fixture scope when discussing evaluation results.
